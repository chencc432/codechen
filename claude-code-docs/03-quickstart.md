# 03. 10 分钟快速上手

本章以一个实际场景走完 Claude Code 的典型使用流程。我们将做一件事：**为一个 Node.js 小工具补全单元测试、修复一个 bug 并更新 README**。

## 场景准备

假设你有一个项目 `todolist/`（本工作区里刚好有一个）。结构类似：

```
todolist/
├── src/
│   ├── index.js
│   └── utils.js
├── package.json
└── README.md
```

## 第 1 步：启动 Claude Code

```bash
cd todolist
claude
```

进入交互界面后，终端会显示当前工作目录和模型名。直接打字与它对话。

## 第 2 步：让它先"摸清"项目

不要一上来就让它改代码，**先让它读项目**：

```text
先帮我看一下这个项目的结构和技术栈，用 200 字总结一下它在做什么，以及目前的代码质量如何。
```

Claude 会主动调用 Read/Glob 等工具读取文件，然后给出一个清晰的总结。此时不要跳过这一步——这能让它后续的输出更精准，也能让你验证它是否真的"理解"了你的项目。

## 第 3 步：让它初始化 CLAUDE.md

```text
/init
```

执行内置 `/init` 斜杠命令，Claude 会生成 `CLAUDE.md`，内容示例：

```markdown
# 项目: todolist

## 技术栈
- Node.js 20
- 无框架（原生 CLI）

## 常用命令
- npm test          # 运行测试
- node src/index.js # 本地运行

## 代码约定
- 所有异步函数使用 async/await
- 使用 2 空格缩进
```

**这份文件以后每次启动 `claude` 都会自动读取**，省去你每次重新解释项目。

## 第 4 步：下达第一个任务（拆解式）

不要说"帮我完善这个项目"这种太泛的话。使用 **任务拆解式** 描述：

```text
我有三件事想让你依次完成，每件事做完先告诉我，不要一次全改：

1. 阅读 src/utils.js，为里面所有导出函数补写 Jest 单元测试，放到 tests/ 目录
2. 在运行测试后，如果发现 bug，先列给我看，我确认后你再改
3. 最后根据新测试和代码更新 README.md 中的"使用示例"章节
```

这种写法的好处：
- **可控**：每一步你都能审阅。
- **可打断**：出现偏差可以中止，不会一口气改 20 个文件才发现方向错了。

## 第 5 步：审阅并批准

Claude 在修改/新建文件前，会显示 diff 预览并询问是否执行。**养成习惯：认真看 diff**。

- 接受 → 回车
- 拒绝 → 输入 `n` 并说明原因，例如："把文件放到 `__tests__/` 而不是 `tests/`"

## 第 6 步：运行测试验证

```text
现在运行 npm test，把失败的测试贴给我看，并说说你打算怎么修。
```

Claude 会执行 shell 命令（首次会询问是否允许），并根据输出分析。

## 第 7 步：结束前的收尾

一个会话结束前，要求它做三件事：

```text
请帮我：
1. 用一句话总结今天修改了什么
2. 列出所有新增/修改的文件
3. 生成一条符合 Conventional Commits 规范的 git commit message（不要执行 commit）
```

这能让你快速写提交说明，也方便日后回顾。

## 新手最容易踩的 3 个坑

### ❌ 坑 1：一句话交代大任务
```
帮我把这个项目从 JS 迁到 TS
```
→ 结果：改了 50 个文件，你根本 review 不过来。

✅ 正确做法：分阶段，先迁核心模块，每一阶段都跑测试。

### ❌ 坑 2：不建立 CLAUDE.md
每次都要重新解释"我们用 pnpm 不是 npm"、"不要用 any"。

✅ 正确做法：第一次就让它 `/init`，然后你手动补充约定。

### ❌ 坑 3：不看 diff 就全部接受
Claude 偶尔会"发散"，改掉你没让它改的文件。

✅ 正确做法：对关键文件逐行看；不确定就让它只改一个文件，你跑通再扩大范围。

## 常用交互命令速查

| 命令 | 作用 |
| --- | --- |
| `/help` | 查看所有可用命令 |
| `/init` | 生成/更新 CLAUDE.md |
| `/clear` | 清空当前上下文（开始新任务前推荐） |
| `/compact` | 压缩历史上下文，省 token |
| `/model` | 切换模型（如 Sonnet ↔ Opus） |
| `/cost` | 查看本次会话消耗 |
| `/review` | 让它对当前改动做代码审查 |
| `/config` | 打开设置 |
| Ctrl+C | 中止当前任务 |
| Ctrl+D | 退出 |
